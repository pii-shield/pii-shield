# PII-Shield v2.2.5 Release Notes

PII-Shield v2.2.5 is a detection and SDK release. It collects every scanner fix merged since v2.2.4: under-redactions closed in URLs, request dumps, JSON and `key=value` pairs, over-redaction removed from model names, setting keys and request lines, and a card detector that no longer calls timestamps cards. It also fixes a security issue in the Node and Python SDKs: without an explicit `salt`, every SDK instance used the same public salt. That fix is the one breaking change (see Breaking Changes). The published WASM kernels for Node and Python are rebuilt with all of it.

## Highlights

- **SDK salt is random when you do not set one (#234).** See Security.
- **Passwords in URLs are hidden (#241).** `postgres://app:hunter2@db`, `redis://:pw@cache` and a generated password with an unencoded `/` in a DSN all passed in the clear.
- **Request dumps and Telegram bot tokens (#236).** A key inside a urllib3/http.client dump (`send: b'...\r\nx-goog-api-key: <key>\r\n'`) and a Telegram bot token in a Bot API URL (`/bot<id>:<token>/sendMessage`) both passed. New signature label `telegram-bot-token`.
- **Model names, setting keys and User-Agent parts stay readable (#239).** `gpt-4o-mini`, `claude-sonnet-5`, `sentence-transformers/all-MiniLM-L6-v2`, `search.max_results` and `Mozilla/5.0` were hidden; on 300 000 real access-log lines the marker count drops from 1 089 702 to 147 030.
- **The card detector requires a real issuer prefix and length (#209).** On 300 000 real access-log lines the Luhn checksum alone found 374 "cards", all 13-digit millisecond timestamps; now 0.
- **Python SDK runs on Apple's own Python (#237).** See SDK Changes.

## Security

### SDK default salt (#234)

When a Node or Python SDK caller did not set `salt`, the WASM kernel used a fixed salt that is public in the source. The tag in `[HIDDEN:xxxxxx]` is an HMAC under that salt, so anyone holding SDK output from such a caller could test a guessed value (an email, a phone number, a short account number) against a tag. The kernel now draws 32 random bytes per instance from `crypto/rand` when no salt is given, the same path the CLI takes without `PII_SALT`, and fails closed if it cannot. Reported privately.

What to do: set `salt` explicitly in every SDK instance and keep it secret. Tags already written by 2.2.4 or earlier SDKs without a salt should be treated as guessable for low-entropy values.

### Under-redaction fixed

Each of these shapes passed in the clear on 2.2.4:

- **URL userinfo (#241).** The password in `scheme://user:password@host` was never scored. It is now always hidden (label `key`, or the issuer label for a known token such as `ghp_…`), including a password carrying an unencoded `/`, `?`, `#` or `@`. `medium.com/@alice`, `unpkg.com/react@18` and `host:8080/users/@alice` are not treated as passwords. Fixed in the same change: a query value inside a quoted or JSON URL is no longer hashed again on a second pass.
- **Request dumps (#236).** A literal `\r\n` glued a header name and its value into one token, and the two backslashes made the scanner treat that token as a Windows path; a `b'...'` bytes literal was cut at its first header. A literal `\r\n` outside quotes now separates tokens, and `b'...'` / `b"..."` is scanned as a quoted string. A `Set-Cookie` value inside a dumped reply is now hidden too.
- **URL paths (#236).** The part of a URL before `?` was never checked. Path segments are now checked against the signature detectors only (no entropy), so a Telegram bot token or a Google key in a path is hidden and ordinary ids and slugs are not.
- **Secret used as a key (#215).** `AKIAIOSFODNN7EXAMPLE=x` passed, even though the bare key is caught. The key half of `key=value` is now scored when it does not look like a field name; field names such as `request_id` or `commit_sha` are never scored.
- **Quoted value containing `=` under a sensitive key (#215).** `{"secret": "<base64>=="}` passed because the value was split on its padding.
- **Long padded base64 blobs (#205).** A 64+ character base64 blob ending in `=` was skipped by design; at the default confidence threshold it is now redacted. At `PII_CONFIDENCE_THRESHOLD` above 1.2 the old behaviour stays.
- **Multi-word quoted value after `key=` (#204).** `note='leak <secret>'` passed; the quoted value is now re-tokenised.
- **Name/setting pairs (#221).** `{"name": "password", "value": "x=hunter2"}` and the logfmt form `name=password value=...` leaked; the value of such a pair is now hidden, and only a `value`/`val`/`values`/`data` key spends the flag, so `{"key": "password", "type": "string"}` keeps `string`.
- **Secret after "password is" (#222).** `my pass is 123456` passed; the force now carries past `is`/`was`/`are`/`were`/`=` after a strong secret word, onto a value shaped like a secret.
- **Escaped JSON inside a JSON string (#220).** With several inner fields the secret leaked; the string is now decoded, scanned and re-encoded.
- **Custom rules on short tokens (#206).** A rule like `^[A-Z]{4}$` never fired, because custom rules only ran on tokens of 5 characters or more. See Behaviour changes.

### Over-redaction fixed

- **Compound identifiers (#239).** A token joined by `-` `.` `_` `/` is scored by its most complex part when every part is word-shaped and the letters read like English. Measured: real model ids hidden 225 of 292 → 13; dotted setting keys 61 of 123 → 6. Thresholds, sensitive keys and context rules still apply.
- **Quoted request lines (#213).** In `"GET /a?_=12345 HTTP/1.1"` the last query value swallowed ` HTTP/1.1"`; the value now ends at whitespace and the closing quote. On 300 000 real access-log lines, `HTTP/1.x` is back on 55 955 lines and the quote count matches the source on every changed line.
- **Timestamps as cards (#209).** See Highlights. Issuer table in `pkg/scanner/bin.go`; Maestro is deliberately not covered (see Known Limitations).
- **Abbreviated commit hashes (#222).** A 7–40 hex value under a commit/sha key (`git_sha=`, `commit_id=`, `"commit":`) is kept.

## Bug Fixes

- **Rescanning redacted output is stable (#219).** A second pass over `password=[HIDDEN:x]` added a marker every time; with entity labels the markers nested. Output of the scanner is now a fixed point.
- **Compact JSON stays valid after a sensitive key (#217).** `{"password":"x","query":"a=b"}` came back as invalid JSON.
- **Escaped JSON inside a JSON string stays valid (#220).**
- **A hidden number in prose is not wrapped in quotes (#222).** `password 123456` used to become `password "[HIDDEN:x]"`; quoting now happens only in value position, where it keeps JSON valid.
- **JSON inside a Python bytes literal (#236).** `b'{"password": "x"}'` lost its closing quote and brace.

## Breaking Changes

- **SDK tags without an explicit salt are now per instance (#234).** Callers who relied on identical tags across processes or restarts without setting `salt` now get different tags per instance. Set the same `salt` everywhere to restore cross-process matching. The CLI is unchanged: it already used a random salt when `PII_SALT` is unset.
- **Python SDK needs Python 3.9 and wasmtime 45 or newer (#237).** See Supported Versions.

**Behaviour changes to be aware of:**

- **Hash values of some markers change.** A quoted secret now hashes like the same secret unquoted (#204), so dashboards that correlate tags across the upgrade will see a break for quoted values.
- **An empty value is no longer hidden (#219).** `password=`, `{"password":""}` and `?token=&` come back unchanged.
- **Dormant custom rules may wake up (#206).** A rule that could never match a short token now does. Example from testing: `^[A-Z]{4}$` went from 0 to 9 323 matches on an unchanged access log, because `HEAD` is four capital letters. Review short-pattern rules before upgrading.
- **Long padded base64 blobs are redacted (#205).** If your logs carry them deliberately (images, payloads), add a `PII_SAFE_REGEX_LIST` rule or raise `PII_CONFIDENCE_THRESHOLD` above 1.2.
- **Request dumps are scanned (#236).** Lines that log `send: b'...'` get the same verdicts as the same text on a line of its own, so User-Agent product tokens and ETags inside dumps may now be hidden where they were not before.
- **Escapes are normalised on changed lines (#220).** On a line where a nested JSON string had something hidden, `\/` becomes `/` and `é` becomes `é`. The JSON stays valid and means the same.

## Known Limitations

- **Word-passwords without a key (#239).** A bare password made of words (`blue-Tiger-42`) with no sensitive key before it is no longer caught, nor is a short random tail behind an ordinary word (`session_Jcnagyqr`). Both are still hidden after a sensitive key. Recorded in `KNOWN_LIMITATIONS.md`.
- **Maestro cards (#209).** Maestro ranges are not in the issuer table, so a Maestro number is only hidden if entropy catches it.
- **Salt rotation (#227).** Tags from before and after a `PII_SALT` rotation do not match; `KNOWN_LIMITATIONS.md` describes how to trace a known identifier under a retired salt.

## SDK Changes

`@aragossa/pii-shield-wasi` 2.2.5 (npm) and `pii-shield-wasi` 2.2.5 (PyPI) ship the rebuilt WASM kernel with every scanner change above and the random default salt (#234). The entity-label docs list the new `telegram-bot-token` label.

### Python SDK no longer killed on Apple's own Python (macOS) (#237)

On macOS, `PiiShield()` killed the whole process with `Killed: 9` (exit code 137) when the interpreter was Apple's `/usr/bin/python3`, the Python 3.9 that ships with Xcode and the Command Line Tools. Homebrew, python.org and pyenv interpreters were not affected, and neither was the Node SDK.

The cause was wasmtime, not the WASM kernel. On macOS wasmtime catches wasm traps by setting Mach exception ports on the thread that first calls into wasm. Apple-signed interpreters guard that port, so the kernel killed the process on the SDK's first call into the module (`EXC_GUARD`, `GUARD_TYPE_MACH_PORT`, `SET_EXCEPTION_BEHAVIOR` in the crash report). Every wasmtime release from 12 to 49 behaves the same way, so pinning wasmtime would not have helped. On macOS the SDK now sets `Config.macos_use_mach_ports = False`, and wasmtime handles traps with POSIX signals, as it already does on Linux. Checked on Apple's Python 3.9.6 and Homebrew Python 3.10 on an M1 Mac: `sdks/python/test.py`, including all 18 parity cases, passes on both. Before the fix the same script was killed on Apple's Python.

## Supported Versions

The `pii-shield-wasi` Python package changes its supported versions:

| | 2.2.4 | 2.2.5 |
| --- | --- | --- |
| Python | `>=3.8` | `>=3.9` |
| `wasmtime` | `>=12.0.0` | `>=45.0.0` |

`wasmtime` 45.0.0 is the first release whose Python API exposes `macos_use_mach_ports`, and wasmtime 45 and later require Python 3.9 themselves. Python 3.8 reached end of life in October 2024. `pip install -U pii-shield-wasi` upgrades an older `wasmtime` automatically. A project that pins `wasmtime` below 45 has to lift that pin. On Python 3.8, pip keeps resolving to `pii-shield-wasi` 2.2.4.

CI now also runs the Python SDK tests on macOS with the runner's `/usr/bin/python3`, alongside the Linux job on Python 3.11.

## Performance

Scoring compound identifiers by their parts (#239) costs time; counting ASCII bytes for Shannon entropy in a 128-entry array (#240) wins most of it back. Output of #240 is byte-identical to the code before it.

## Upgrade Notes

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.2.5
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.2.5
```

```bash
npm install @aragossa/pii-shield-wasi@2.2.5   # Node
pip install --upgrade pii-shield-wasi==2.2.5  # Python
```

SDK users: set `salt` explicitly before upgrading if you need tags to match across processes (see Breaking Changes).

The operator's gRPC dependency moved to v1.83.1 for GO-2026-6348 (#208), and the operator's envtest integration suite now runs in CI (#225).
