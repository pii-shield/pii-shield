# PII-Shield v2.2.6 Release Notes

PII-Shield v2.2.6 is a detection release. It collects the five scanner fixes merged since v2.2.5: three close under-redactions (Python bytes values and binary data, short values after a key that names a secret, the value after long secret field names such as `aws_access_key_id`) and two remove over-redaction (snake_case identifiers and very short words in prose, camelCase names with a number such as `s3BucketName`). There are no breaking changes. The published WASM kernels for Node and Python are rebuilt with all of it.

## Highlights

- **Python bytes values and binary data are hidden (#250).** `{b'authorization': b'Basic <base64>'}`, the way Python logs a dict of bytes headers, passed in the clear, and so did Kerberos keys printed as `b'0\x81\x9a...'`.
- **`aws_access_key_id=...` hides its value (#247).** The key is in the default sensitive-key list, but an entropy guard rejected it before the list was checked.
- **`{"password": "ab"}` is hidden like `{"password":"ab"}` (#249).** A space after the colon decided whether a short value survived.
- **Identifiers stay readable (#245, #251).** `token_value`, `not_found`, `s3BucketName`, `http2Enabled` and `krb5KeyVersionNumber=3` were hidden as if they were secrets.

## Security

### Under-redaction fixed

Each of these shapes passed in the clear on 2.2.5:

- **Python bytes values under a sensitive key (#250).** In `{b'authorization': b'Basic <base64>='}` the value skipped the bytes-literal handling, reached the `key=value` splitter, was cut on its base64 padding and written out unscored. It is now hidden whole, like the same `str` value. Seen in a WebDAV server that logs `request.headers` at DEBUG.
- **Binary bytes literals (#250).** A literal holding binary data (`b'0\x81\x9a\xa0...'`, an LDAP modlist with Kerberos keys at DEBUG) was cut by its escapes, spaces and brackets into short fragments, and each passed on its own. A literal with at least four `\xNN` escapes whose bytes are not valid UTF-8 is now scored as one blob by entropy. Random bytes score far above the threshold; a run of zero bytes or a short protocol header stays. Non-Latin text sent as bytes (`b'\xd0\x9f\xd1\x80...'`) decodes as UTF-8 and is scanned as text, as before.
- **Short value after a quoted key that names a secret (#249).** `{"password": "ab"}` and `{"x-api-key": "abc"}` came back unchanged, while the compact `{"password":"ab"}` was hidden. After a quoted key that names a secret outright (a whole sensitive-key entry, a run of words such as `api_key` inside `x-api-key`, or a strong word such as `password` or `token`), a short value is now hidden. Keys where the word only sits inside another word (`author`, `keywords`), a lone weak word (`{"key": "value"}`), unquoted keys and literals (`true`, `null`, `None`) are unchanged.
- **Long secret field names (#247).** `aws_access_key_id`, `AWS_ACCESS_KEY_ID`, `aws_secret_access_key`, `aws_session_token` and `github_access_token` did not force their value, because a guard for long, random-looking keys fired on the partial match `key` or `token` first. The guard now lets through an exact entry of the sensitive-key list, and a name of letters joined by `_` or `-` with a segment `password`, `passwd`, `passphrase`, `secret` or `token`. Weak words (`key`, `sign`, `auth`, `pass`) do not qualify, so long names such as `keycap_digit_one` and `Keyword.Namespace` keep the guard.

### Over-redaction fixed

- **Lowercase snake_case identifiers (#245).** `token_value`, `not_found` and `read_write` sat on the threshold because the underscore adds a character class, and were hidden by plain entropy. They are now kept unless they match a signature (`sk_live_…`). Anything with a digit or a capital is still scored, and a sensitive key still forces its value (`password=secret_value` is hidden).
- **One- and two-character tokens in prose (#245).** A bare sensitive word forced its next token, so `self.auth[0]` and `the password 0 is` lost the `0`. In prose a token shorter than three characters is no longer forced; `cvv 123` stays hidden, and the value right after `password:` or `password=` is forced whatever its length.
- **camelCase names with a number inside a word (#251).** As the key of `key=value` (`krb5KeyVersionNumber=3`, `s3BucketName=logs`) the name was hidden, because only trailing digits (`http2`, `sha256`) counted as a field name. As a plain word or a quoted value (`field s3BucketName changed`, `('s3BucketName', 7)`) the digit pushed the whole name over the threshold. Such a name is now a field name when it is strict camelCase, and as a word it is scored part by part, like `gpt-4o-mini`. A name that contains a sensitive word keeps its whole-token score, so `krb5KeyVersionNumber` is still hidden as a bare word (it contains `key`); as a key it is kept.

## Bug Fixes

- **A hidden bytes value keeps its `b''` (#250).** `{b'password': b'x'}` became `{b'password': [HIDDEN:…]}`, and `password=b'x'` lost the prefix the same way; the repr is now still a bytes literal.
- **A query flag glued to a marker is stable on rescan (#245).** On a second pass `?token=[HIDDEN:x]&aB3dE9` hid `&aB3dE9`, which the first pass keeps.

## Breaking Changes

None.

**Behaviour changes to be aware of:**

- **Hash values of hidden bytes values change (#250).** The tag of `b'<secret>'` under a key is now the tag of `<secret>`, the same as for `'<secret>'`; on 2.2.5 it was the hash of the whole literal, prefix included.
- **More short values are hidden (#249).** Short values after quoted keys that name a secret. Measured on 906 077 distinct lines of Go and Python source: 5 new redactions, all dict literals in code (`"password": str`).
- **Values after long secret field names are hidden (#247).** On the same source trees: 16 new redactions, all type annotations and constants in code, and 119 lines lose one.
- **Fewer identifiers are hidden (#245, #251).** On the same source trees #245 removed 4 347 spurious redactions and added none.

## Known Limitations

- **Short random tokens shaped like camelCase names (#251).** A secret that happens to be strict camelCase with a number inside a word (`ZfUj2Cwy`) passes when it is used as a key, and as a bare word some short ones drop under the threshold: 139 of 20 000 random base62 tokens of 8 characters, 63 of 12, 12 of 16, none of 24 or more. Recorded in `KNOWN_LIMITATIONS.md`.

## SDK Changes

`@aragossa/pii-shield-wasi` 2.2.6 (npm) and `pii-shield-wasi` 2.2.6 (PyPI) ship the rebuilt WASM kernel with every scanner change above. No API changes.

## CI

- The Performance Check now compares the scanner benchmarks of a pull request with its base branch instead of fixed numbers (#246), and fails when a benchmark is significantly slower than the base by more than 10% (#248).
- Dependency updates: GitHub Actions group (#244), operator Go dependencies including `k8s.io/*` v0.37.1 and gomega 1.44.0 (#243).
