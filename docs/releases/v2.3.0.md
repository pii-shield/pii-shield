# PII-Shield v2.3.0 Release Notes

PII-Shield v2.3.0 is the last minor release of the 2.x line. It makes the scanner faster than it has been since v2.2.0 (about 1.5× v2.2.8 on text and JSON logs and 1.85× on nginx access logs, one core), adds three key-based detectors (one-time codes, dates of birth, medical record numbers), closes eight under-redactions and four over-redactions, buffers the CLI's output, hardens the operator's pod security, and raises the Helm chart's sidecar CPU limit from 50m to 250m. CI now fails a pull request that is more than 15% slower than the accepted baseline, so the drift that cost v2.2.0 → v2.2.8 a fifth of its throughput cannot repeat unnoticed. The README's throughput numbers are measured, dated and tied to a machine. There are no breaking changes for CLI, container, Helm, operator or SDK users; two behaviour changes are listed under Breaking Changes. The published WASM kernels for Node and Python are rebuilt with every scanner change.

## Highlights

- **Throughput (#306, #307, #310, #311, #312, #313).** On one Apple M1 core, CLI reading stdin and writing a file, 200 000-line corpora, median of 5: text logs 61.6k → 92.4k lines/s, JSON logs 59.2k → 89.9k, nginx access logs 28.5k → 52.8k. Each optimization was checked byte for byte against the `main` it branched from on 1.4 million lines; none changes what is hidden.
- **One-time codes, dates of birth and medical record numbers are hidden under their keys (#299, #300).** `{"newPassword": "…", "otp": "483920"}`, `dob=1986-12-01`, `mrn: 00428173` passed on v2.2.8.
- **An `<e-mail>:<password>` pair is hidden, both halves (#296).** `login lena@example.com:hunter2` came back unchanged; `git@github.com:org/repo.git` still stays.
- **A Python `LEVEL:logger:` prefix no longer poisons the message (#295).** A logger named `auth` or `app.token` hid the first word of every message it wrote.
- **Chart default resources (#315).** The sidecar's CPU limit is 250m (request 100m) instead of 50m/50m: the sanitizer is a single thread, and 50m capped it near 4.5k lines/s. A sizing table (limit → lines/s) is in `docs/sidecar-failure-modes.md`.

## Features

### One-time codes, dates of birth, medical record numbers (#299, #300)

Three more values that nothing about their shape distinguishes from harmless numbers and dates are now hidden by the key they sit under, in text, JSON, logfmt and URL queries:

- **One-time codes.** 4 to 8 digits as the value of a key whose last word is `otp`, `totp`, `passcode`, or a `code` qualified by the word before it (`otp_code`, `verification_code`, `mfa_code`, `reset_code`). Marker label `key`.
- **Dates of birth.** A calendar date (`1986-12-01` with an optional time, `01/12/1986`, `12/01/1986`, `1.12.1986`) under `dob`, `birth_date`, `date_of_birth`, `birthday`. New marker label `dob`.
- **Medical record numbers.** Digits under `mrn` or `medical_record_number`, handled like an identity number. Marker label `id-number`.

`created_at=1986-12-01`, `status_code=200` and `zip_code=10115` are unchanged: the key has to name the value.

### Buffered CLI output (#310)

The CLI used to write every sanitized line with its own `write` system call, 12–25% of its wall time on a busy stream. Lines now go through a 64 KiB buffer flushed when it fills, every 50 ms, right after a `[PII_SHIELD_DROP: …]` or `[PII_SHIELD_WARN: …]` marker, and on every shutdown path (EOF, SIGTERM, SIGINT, a read error). After the shutdown flush the writer passes every further line straight through, so nothing is left in a buffer while the metrics server drains. The two overflow markers that were written to stdout directly now go through the same writer, so they cannot overtake buffered lines.

New setting: `PII_OUTPUT_FLUSH_INTERVAL` (Go duration, default `50ms`). `0` restores one `write` per line. See CONFIGURATION.md, section Output.

### Performance gate against an accepted baseline (#308)

The "Performance Check" job compared each pull request with its base only, so slowdowns of a few percent each added up to −20% between v2.2.0 and v2.2.8 without a single red run. It now also compares the branch with the ref in `benchmark/baseline-ref` (v2.2.8): a significant slowdown above 8% is a warning with the benchstat table in the job summary, above 15% the job fails. The per-PR comparison warns above 5% and fails above 10% as before. Accepting a slowdown on purpose means moving `benchmark/baseline-ref` in the same pull request. A third benchmark, 512 lines in the shape of an nginx access log, joins the two short ones; it is copied into the base checkout so both sides run the same code.

### Chart: sidecar CPU limit 250m (#315)

`charts/pii-shield/values.yaml` sets `resources.limits.cpu: 250m` and `resources.requests.cpu: 100m` (memory 30Mi unchanged). Throughput is the CPU limit times the per-core rate, so 250m sustains about 22k lines/s on text or JSON logs and 13k on access logs; the former 50m default capped the sidecar near 4.5k and 2.6k, and a busier application left the sanitized stream lagging. The operator still sets no default: give `PiiPolicy.spec.resources` a limit from the table in `docs/sidecar-failure-modes.md`.

## Performance

All numbers: one Apple M1 core (`GOMAXPROCS=1`), Go 1.27.3, CLI reading stdin, 200 000-line corpora, median of 5 runs. The access-log corpus is the first 200 000 lines of a real nginx log (312 bytes per line, a User-Agent on every line); text and JSON are generated.

| lines/s | v2.2.0 | v2.2.8 | v2.3.0 | vs v2.2.8 |
|---|---|---|---|---|
| text, into a file | 73.8k | 61.6k | 92.4k | +50% |
| JSON, into a file | 65.3k | 59.2k | 89.9k | +52% |
| access log, into a file | 37.8k | 28.5k | 52.8k | +85% |
| text, into a pipe | — | 69.9k | 96.9k | +39% |
| JSON, into a pipe | — | 67.8k | 89.7k | +32% |
| access log, into a pipe | — | 31.0k | 53.0k | +71% |

Where it comes from:

- **Sensitive keys are matched in one pass (#306, #307).** Every bare token was lowercased and checked with `strings.Contains` once per entry of the sensitive-key list, 13–20% of scan time. The entries are compiled into an automaton once per configuration; a key costs one table step per byte whatever the list's length. CLI +10% on text and JSON, +19% on access logs.
- **Buffered output (#310).** +24% into a file, +8% into a pipe (see Features).
- **Bigram scores from a table (#311).** The English bigram table was a map keyed by a two-byte string, hashed once per pair of every token; it is now a `[128][128]` array built per configuration with the default score filled in. +4%.
- **No lowercase copy per token (#312).** The case-insensitive checks in the token loop read a copy from `strings.ToLower` for every token; an ASCII token is now lowered into a stack buffer. Time within noise, 3–7 fewer allocations per line (13 → 6 on an access-log line).
- **Card windows capped by the digit run (#313).** The Luhn scan re-checked the connectivity of every window from its first digit for each of seven lengths; the run is found once per start. The scan itself −58%, +3–4% end to end.

A bisection over the 67 scanner commits between v2.2.0 and v2.2.8 found no commit that slowed the scanner without changing what it hides: the loss was the sum of detection changes of 1–4% each, the largest the compound-of-words scoring that keeps model ids, setting keys and logger names (#239, #261, #262). None was reverted.

## Security

### Under-redaction fixed

Each of these shapes passed in the clear on v2.2.8:

- **A short quoted value under a key from `PII_SENSITIVE_KEY_PATTERNS` or with a `pw`/`pwd` component (#294).** `{"first_name": "Lena"}` under the pattern `(^|_)name$` and `{"db_pwd": "ab"}` kept values of 2 to 5 characters that `{"password": "Lena"}` hid; the key now names a secret outright, as `password` does.
- **A value inside a Python log message (#295).** With the default `LEVEL:logger:message` format, the prefix was read as a key, so a key or a bare `password` word inside the message lost its force. The prefix is framing now and the message is read on its own.
- **`<e-mail>:<password>` (#296).** `login lena@example.com:hunter2` and `creds=lena@example.com:Winter7413#` came back unchanged because the pair looked like an scp target. Address and password are both hidden unless the part after the colon is a path, a file name or a port; `git@github.com:org/repo.git` stays.
- **A password ending in `?` (#297).** `password=Kaffee1977?` and `password="Kaffee1977?"` went to the URL handling whole and passed. A token without a scheme is a URL only when a `name=value` pair follows the `?`.
- **One-time codes, dates of birth, medical record numbers (#299, #300).** See Features.
- **A credential after any auth scheme word (#301).** `Authorization: QBox <ak>:<sig>=`, `accessToken: Qiniu …`, `Authorization: AWS <key>:<sig>` and `SSWS <token>` were hidden only after `Basic` and `Bearer`. Any scheme word in a sensitive key's value slot now forces the credential, and a forced value with a colon inside is hidden whole instead of being split as a key:value pair.
- **Both copies of a value in a SQL dump row (#304).** A single-quoted SQL literal holding JSON is read as one token, and a value between escaped quotes or backticks is judged without its framing: both copies of an address in `INSERT … VALUES ('{"email":"…"}', '…')` are hidden, the JSON inside stays valid, and a backticked table name is kept.

### Over-redaction fixed

- **The first word of every Python log message under a logger named `auth` or `app.token` (#295).**
- **Thread names with a two-letter first word (#302).** `DbWorker_0`, `IoWorker_3`, `OkHttpClient_2` in a log prefix were hidden. The rule costs 9 more kept tokens of 5 000 random mixed-case ones, against 253 for the broader rule rejected in #265.
- **Product tokens and the contact address in a User-Agent (#303).** `AhrefsBot/6.1`, `MJ12bot/v1.4.8`, `Mobile/11A465` and `+http://ahrefs.com/robot/` inside a quoted User-Agent were hidden; they are written as they are and the rest of the string is scanned as before.
- **A database identifier after the bare word `key` (#305).** MySQL's `Duplicate entry 'x' for key 'users.email'` lost the index name (`users.email`, `order_items.PRIMARY`, `idx_user_email`); an identifier made of words is scored on its own instead of being forced.

### Operator and sidecar hardening (#309)

The operator pod's `securityContext` is a chart value with restricted defaults; the injected sidecar drops all capabilities and runs with the `RuntimeDefault` seccomp profile; the pipe-mode `mkfifo` init image is pinned to `alpine:3.20`. Closes #52.

## Bug Fixes

None outside the scanner changes above.

## Breaking Changes

None for the CLI, the container images, the Helm charts, the operator and the SDKs.

**Behaviour changes to be aware of:**

- **Output latency (#310).** A sanitized line leaves the CLI up to 50 ms after it was read, or when 64 KiB have accumulated, instead of at once. A `DROP`/`WARN` marker is still written immediately, and every line is flushed before the process exits. A pipeline that needs each line the moment it is sanitized sets `PII_OUTPUT_FLUSH_INTERVAL=0`.
- **Chart resources (#315).** An install of `charts/pii-shield` with default values now requests 100m and limits the sidecar to 250m CPU. Overrides in your values file win as before.
- **More values are hidden.** One-time codes, dates of birth and medical record numbers under their keys; `<e-mail>:<password>` pairs; passwords ending in `?`; credentials after any auth scheme word; short quoted values under pattern-matched and `pw`/`pwd` keys; both copies of a value in a SQL dump row.
- **Fewer values are hidden.** Two-letter-prefixed thread names, User-Agent product tokens and contact addresses, database identifiers after the bare word `key`, and the first word of Python log messages under a logger whose name is a sensitive word.
- **New marker label `dob`** when `PII_ENTITY_TYPE_LABELS=true`; one-time codes carry `key`, medical record numbers `id-number`.
- **Operator pod security (#309).** The operator deployment now carries a restricted `securityContext` by default; a cluster policy that forbade it did not apply before.

## Known Limitations

Added or updated in KNOWN_LIMITATIONS.md:

- An identity number, a one-time code and a date of birth are found only under a key that names them; a bare `483920` or `1986-12-01` in free text is not hidden (#299, #300).
- An auth scheme's credential is hidden after a key and a separator, not inside one token (#301).
- A User-Agent's product tokens and its contact address are written as they are, including a bot's own contact e-mail (#303).

Still open, found while closing the above: a password made of dictionary words after the bare word `password` in prose (`password Wintermonkey73`); a session value followed by another `k=v` pair inside a quoted cookie list; a secret in the last path segment of a quoted URL without a query. Each has a tracker entry and a reproduction.

## Upgrade Notes

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.3.0
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.3.0
```

The sidecar chart's default CPU request and limit change (100m / 250m); keep your own `resources` block if you set one. The operator chart renders a restricted `securityContext` for the operator pod; override `securityContext` in its values if your cluster needs something else.

```bash
npm install @aragossa/pii-shield-wasi@2.3.0   # Node
pip install --upgrade pii-shield-wasi==2.3.0  # Python
go get github.com/pii-shield/pii-shield/v2/pkg/scanner@v2.3.0  # Go
```
