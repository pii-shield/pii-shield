# PII-Shield v2.2.1 Release Notes

PII-Shield v2.2.1 is a patch release. It fixes two over-redaction bugs that surface when a whole document — a git diff, a log batch — is passed to the scanner at once: the WASM SDKs scored the last token of every line together with its newline, and git diff header lines lost their file names and object hashes. There are no breaking changes and no configuration changes.

## Highlights

- Node and Python SDKs: `redact()` now scans multi-line input line by line and preserves `\n` / `\r\n` endings, so a value at the end of a line is scored on its own and the output keeps the input's line count.
- Scanner: git diff header lines (`diff --git a/… b/…`, `--- a/…`, `+++ b/…`, `rename`/`copy from|to`, `Binary files …`) and `abc1234..def5678` hash ranges pass through unchanged.

## Bug Fixes

### WASM `redact()` treated multi-line input as one line (#184)

The WASM entrypoint handed the entire input buffer to the single-line engine, where `\n` is not a token separator. The last token of every line therefore carried its newline — often together with the first token of the next line — so structural safe rules such as the plain-decimal rule never matched and the token fell through to the entropy scorer: `4532015112.830366\n` came back as `[HIDDEN:entropy:…]` while `4532015112.830366` on its own was left alone. The newline swallowed inside the marker also disappeared from the output, so a 10-line diff could come back as 6 lines.

The new `scanner.ScanAndRedactText` scans each line independently and keeps the line endings; `cmd/wasm-ffi` uses it. The CLI, which already read stdin line by line, is unchanged. Reported by a downstream GitHub Action that feeds whole diffs to `redact()`; reproduced on the 2.1.1 and 2.2.0 wheels, so this is a long-standing behaviour, not a regression.

### Git diff header lines redacted as entropy (#186)

`a/` and `b/` relative paths score above the default 3.6 threshold (`a/report.csv` 3.92, `b/Dockerfile` 4.42) and the abbreviated `3b18e51..a1c9f02` range on the `index` line scores 4.58, so a sanitized diff lost every file name and stopped being a valid patch. Two structural safe rules fix this without touching thresholds: a top-level line that starts with a git diff header is passed through as is (header lines carry paths and hashes only, never values), and a `<hex7-40>..<hex7-40>` token is treated like a git hash. Diff body lines (`+`, `-`, space) are scanned exactly as before; a secret on a `+password=…` line is still redacted.

A bare relative file name on its own (`report.csv`, `src/main.go`) can still score above the threshold; that is a separate, wider false positive and is not changed in this release.

## Breaking Changes

No breaking changes. No salt, credential, or configuration changes are required. Default-behaviour changes to be aware of: SDK callers that passed multi-line text now get line-by-line scanning (secrets on inner lines are still redacted; the line count is now preserved), and git diff header lines are no longer redacted.

## SDK Changes

- `@aragossa/pii-shield-wasi` 2.2.1 (npm) and `pii-shield-wasi` 2.2.1 (PyPI) ship the rebuilt WASM kernel with the multi-line fix. The SDK APIs are unchanged; the READMEs document the multi-line contract.
- The cross-entrypoint parity golden (`sdks/parity/cases.json`) gained two multi-line cases, asserted identically by the Go API, Node, and Python.

## Upgrade Notes

Upgrade Helm deployments by updating the chart repository and installing the `2.2.1` chart versions:

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.2.1
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.2.1
```

SDK consumers:

```bash
npm install @aragossa/pii-shield-wasi@2.2.1   # Node
pip install --upgrade pii-shield-wasi==2.2.1  # Python
```
