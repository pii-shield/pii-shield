# PII-Shield v2.2.7 Release Notes

PII-Shield v2.2.7 is a detection release. It adds two detectors, for telephone numbers and for identity numbers under a key that names them, hides e-mail addresses by their shape instead of by their score, and collects thirteen scanner fixes merged since v2.2.6, which close ten under-redactions and remove five over-redactions. Most of them were found by running the released scanner against log shapes taken from public bug reports and public code. There are no breaking changes. The published WASM kernels for Node and Python are rebuilt with all of it.

## Highlights

- **Telephone numbers are hidden (#254).** `mobile=09122654130`, `"wa_id": "4917412345678"`, `+49 170 1234567` and `(555) 234-5678` passed in the clear, because digits alone never reach the entropy threshold. New label `phone`.
- **Identity numbers under their key are hidden (#272).** `"idNumber": "141638835"`, `ssn: 078-05-1120` and `?national_id=…` passed in the clear for the same reason. New label `id-number`.
- **An e-mail address is hidden whatever it looks like (#260, #264).** `marcosantos@corp.example` and `lena_santos@example.com` passed while `lena.becker@example.com` was hidden; an address right before a colon (`for user 'lena@example.com': …`) passed every time.
- **A secret in the middle of a chain of assignments is hidden (#269).** A key on a middle line of a `.env` dump inside a JSON string, and the password in `Login=tom&Password=…&RememberMe=true`, were written out as an unscored key name.
- **The default Python log format no longer hides the key from the scanner (#263).** `DEBUG:pkg.module:Password: <value>` and `INFO:root:password=<value>` let a word-like password through.
- **`Authorization: Basic <base64>` is hidden whatever its score (#257).**
- **A key used as a URL path segment is hidden (#259).** `http://gateway/app/<32-hex key>/v1/chat/completions` kept the key.
- **Log prefixes stay readable (#256, #261, #262, #265).** ISO timestamps with milliseconds, dotted logger names (`flaskUI.v2restapi`, `org.apache.kafka.clients.NetworkClient`), camelCase names (`SecurityCtrlr`) and thread names (`SyncWorker_3`) were hidden as if they were secrets.

## Features

### Telephone number detector (#254)

Three shapes are found, in text, JSON and logfmt values and in URL parameters:

- international with a leading `+`: 8 to 15 digits, compact (`+4917412345678`) or grouped (`+49 170 1234567`, `+1 (555) 234-5678`);
- North American 3-3-4 with a parenthesised area code or one uniform `-` or `.` separator (`(555) 234-5678`, `555-234-5678`);
- 7 to 15 digits as the value of a key whose last word names a phone: `phone`, `phone_number`, `mobile`, `tel`, `msisdn`, `cell`, `fax`, `whatsapp`, `wa_id`, `contact_number`.

Bare digits under any other key (`"from": "4917412345678"`) stay, on purpose: they cannot be told from an order id or a millisecond timestamp. The label is `phone` when `PII_ENTITY_TYPE_LABELS` is on, the metrics type is `signature`, and `PII_SAFE_REGEX_LIST` applies. Measured on 300 000 real access-log lines: 33 lines changed, each with a real number in `mobile=`, `telephone=` or `emailOrMobile=`.

### Identity numbers under a key (#272)

A national id, a social security number or a passport number is digits only, like a phone, and no checksum tells it from a timestamp or an order id: every country has its own, and one bare nine-digit number in ten passes a mod-10 check. So the number is known by its key. 6 to 15 digits, compact or in groups (`078-05-1120`, `123.456.789-09`), are hidden as the value of a key whose last words name an identity document: `idNumber`, `id_number`, `childIdNumber`, `national_id`, `tax_id`, `citizenId`, `identity_number`, `ssn`, `social_security_number`, `passport`, `passport_number`, `cpf`, `dni`, `nin`, `tin`, `aadhaar`, `teudat_zehut`.

It works in text, in JSON and logfmt values and in URL parameters. A record id (`id`, `user_id`, `order_id`, `order_id_number`) and a key that only starts with such words (`ssn_verified`, `id_number_type`) are left alone. The label is `id-number`, the metrics type is `signature`, and `PII_SAFE_REGEX_LIST` applies. Measured on 300 000 real access-log lines and 16 143 application-log lines: no line changed, neither corpus has such keys.

## Security

### Under-redaction fixed

Each of these shapes passed in the clear on 2.2.6:

- **E-mail addresses with a word-like local part (#260).** An address was scored by entropy alone: 27 of 4 212 generated first-name plus last-name addresses passed. A token with the shape of exactly one address is now hidden by that shape, in text, under a key and as a URL parameter (`?email=…`); label `email`. A hostname with a user (`ubuntu@ip-10-0-0-1.ec2.internal`) has the same shape and is hidden too. `@handle`, `pkg@v1`, `user@localhost` and `git@github.com:org/repo.git` keep their text.
- **An e-mail address directly followed by a colon (#264).** `Password reset key for user 'sven.fischer40@example.com': 543963` kept the address, with single or double quotes and without. The token before a colon is the key half of a pair and was written out unscored. Quotes and colon are kept, and JSON stays valid when the address is an object key.
- **A secret between two assignments in one token (#269).** In `{"content": "$ cat .env\nGITHUB_TOKEN=ghp_…\nDEBUG=false\n"}` and in `Login=tom.doe&Password=…&RememberMe=true` the splitter cut the token at its first `=` and took `<secret>\nDEBUG` or `<secret>&RememberMe` as a key name, which is written out unscored; a known prefix did not help. The token is now cut where a new assignment starts: at a line break written as `\n` and at a `&`, when a field name and `=` follow. URLs keep their own parameter handling. 40 random values per shape: 0 of 40 hidden on 2.2.6, 40 of 40 now, for `sk-proj-…` and `ghp_…` keys in a `.env` dump and for `Password=` and `client_secret=` in a form body.
- **A sensitive key glued to the Python log prefix (#263).** `logging.basicConfig` writes `LEVEL:logger:message` with no space. `DEBUG:huawei_lte_api.Connection:Password: Wintermonkey73` and `INFO:root:password=Wintermonkey73` lost the key, so only a random-looking value was caught, by its score. A line with the prefix is now redacted exactly like the same message on its own.
- **A bare secret in front of a colon (#270).** `key <secret>: rejected`, `token <hex>: rejected` and the Go and Rust error form `for key <secret>: reason` passed, while the same value followed by a comma or a full stop was hidden. A bare token before a colon is now scored when it does not look like a field name. Names, log levels, host names, numbers, commit hashes and 12-character Docker layer ids (`3f4e5d6c7b8a: Pull complete`) are written as before.
- **`Authorization: Basic` credentials (#257).** `Authorization: Basic bGVuYTpqcjBYUWdVaVpSRjM=` passed: the base64 of `user:password` can score below the threshold, and its `=` padding sent it through the `key=value` splitter. The token after `Basic`, right after an authorization key, is now hidden when it has the base64 shape. `basic` as a word in prose keeps its neighbours.
- **A compact JSON pair whose value holds an `=` (#257).** `{"password":"hunter2=x"}` passed whole and `{"authorization":"Basic <base64>="}` came back as broken JSON. Such a pair is now split at its colon first.
- **A key in a URL path (#259).** `POST http://llm-gw.example.org/mathutrice/<32-hex key>/v1/chat/completions` kept the key. In a URL with a scheme, a path segment of 20 to 128 characters from `[A-Za-z0-9_-]` with a letter and a digit is now scored like a value. A 40-hex commit, a 24-hex object id, a UUID, a 64- or 128-hex digest, snake_case names and any segment with `%` or `.` are written as before.
- **`pw` and `pwd` as key names (#258).** `PW:maple248`, `db_pw=…` and `smtp_pwd=…` did not force their value. `pw` counts as a whole component of a key, `pwd` as one component of several; a bare `PWD` stays the shell's working directory.
- **The value under `attributeValue` after a secret name (#271).** `{"name": "password", "value": "…"}` already made the value sensitive, but only under `value`, `val`, `values` or `data`. An OCPP 2.0.1 `SetVariables` frame carries it as `attributeValue`; a key whose last word is `value` now counts too.

### Over-redaction fixed

- **ISO 8601 timestamps with a fraction (#256).** `2026-09-27T14:15:31.478Z`, the default time format of pino, winston and most JSON loggers, came back as `2026-09-27T14:15:[HIDDEN:…]` for about 30% of timestamps.
- **A word after a bare sensitive word in prose (#258).** `token expired`, `authentication failed for bob` and `key rotation done` lost the word after the sensitive one. An all-letter word that reads as English is now kept; a value with a digit or symbol (`password hunter2`) and any value after `:` or `=` are hidden as before.
- **Dotted logger names (#261).** `flaskUI.v2restapi`, `services.v1client` and `org.apache.kafka.clients.NetworkClient` were hidden on every line of a Python or Java log. On 300 000 real access-log lines 2 126 lines lose a marker, all of them class names in one parameter.
- **camelCase names with no separator (#262).** The OCPP component name `SecurityCtrlr` was hidden even alone on a line. On the same access log 1 329 lines lose a marker (`productModel`, `GoogleImageProxy`).
- **Thread names in a log prefix (#265).** `(SyncWorker_3)` in a Home Assistant log was hidden on every line from a worker thread, and any word-like name in brackets right after `WARNING` or `ERROR` was scored against the lowered threshold.

## Bug Fixes

- **A card or phone found in a line no longer flips the quoting of the rest of the line (#254).** The User-Agent after a number in a quoted request line was hidden, and `{"phone": "…", "token": "x"}` lost the quotes of the next field.
- **Operator: OpenTelemetry updated to v1.45.0 for GO-2026-6505 (#266).**

## Breaking Changes

None.

**Behaviour changes to be aware of:**

- **More values are hidden.** Telephone numbers in the three shapes above; digits under an identity key; every e-mail address, including a hostname with a user; a 32-character hex MD5 or trace id in the path of a URL with a scheme, which has the same shape as the key that rule is for (500 of 500 in the test set), and a 44-character Google Docs id.
- **A dictionary word right after the bare word `password` in prose can pass (#258).** This is the cost of keeping `token expired` readable: of 1 500 generated lines with a bare word password, 1 375 were hidden before and 366 after. A password with a digit or symbol, and any password after `:` or `=`, is hidden as before. `KNOWN_LIMITATIONS.md` already said that a word password written bare is not reliably found.
- **Fewer names are hidden (#261, #262, #265).** Marker counts drop on logs with dotted logger names, camelCase names and indexed thread names.
- **Throughput (#254).** The phone detector adds one pass over each line: end-to-end median +3.2% on 500 000 lines.

## Known Limitations

Added to `KNOWN_LIMITATIONS.md` in this release:

- **An identity number is only found under a key that names it.** A number in prose (`the id number 141638835 was checked`), one under a record-style key, a document number with letters under a key that is not sensitive (`"nino": "QQ123456C"`) and a key in another language are not found; add a custom regex or a sensitive-key pattern for them.
- **A name/value pair is read left to right.** `{"name":"password","value":"…"}` hides the value; `{"value":"…","name":"password"}` does not force it, and the value is then judged by its own score. The same holds for an OCPP frame with `attributeValue` before the variable name.
- **A value named only by the words around it.** In `recovery code gyrpm-xjjxx rejected` the words `recovery code` are not a key, and a short lowercase code can score under the threshold. As a key (`recovery_code=…`) it is forced once `PII_SENSITIVE_KEY_PATTERNS=recovery` is set.
- **A two-part code whose parts have the same length is hidden.** `GAIA_RE01` (a Kintone error code) and `ASUS_T00N` (a phone model) are taken for a generated code. Relaxing the rule let random upper-case codes joined by `_` through, so it stays; a `PII_SAFE_REGEX_LIST` rule keeps the codes you need.

Still open from the fixes above: a thread name whose first word is two letters (`DbWorker_0`) is hidden; a bare key with no separator after the Python prefix (`DEBUG:root:password hunter2`) is not seen as a key; `lena@example.com:hunter2` is left as it is, because the same shape is an scp target.
