# PII-Shield v2.2.3 Release Notes

PII-Shield v2.2.3 is a patch release with one detection fix: the leading `+` / `-` marker of a diff body line is no longer scored as part of the first token, so an ordinary word or file name on an added line is not redacted. There are no breaking changes and no configuration changes.

## Highlights

- Scanner: a diff marker glued to the first token of a line is treated as framing rather than data. `+report.csv`, `+config.yaml`, `+src/main.go`, `+Traceback` and their `-` equivalents are no longer redacted.

## Bug Fixes

### Diff marker glued to the first token of a line (#192)

`+` and `-` are not token separators, so `+report.csv` reached the scorer as a single token and the marker contributed a character class to the class bonus. The effect is large on short, low-entropy tokens:

| token | score | threshold 3.6 |
| --- | --- | --- |
| `Traceback` | 1.73 | clean |
| `+Traceback` | 3.92 | redacted |
| `report.csv` | 3.62 | clean (safe rule, #189) |
| `+report.csv` | 3.78 | redacted |

`-report.csv` was clean only by accident: `-` is a legal file-name character, so the whole token matched the file-name rule from #189, while `+` is not and could not.

A leading run of at most two `+` / `-` bytes (two, for combined `diff --cc` output) is now emitted verbatim and the rest of the line is scored on its own. Output stays byte-for-byte, so line counts and patch validity are unaffected, and the git diff header check from #186 still runs first.

Detection is preserved wherever the remainder alone is detected, and this is covered by regression tests: `+password=…`, `-password=…`, `+AKIAIOSFODNN7EXAMPLE`, `+Zq8vN3pL7xR2wT9yB4mK6`, `+4532015112830366`, `+alice@example.com` and `--flag=…` all stay redacted.

Reported by a downstream user running whole git diffs through the WASM SDK, as a residual of the fixes released in 2.2.1 and 2.2.2.

## Breaking Changes

No breaking changes. No salt, credential, or configuration changes are required.

**Behaviour change to be aware of:** a bare signed integer is no longer redacted. `-123456789012` and `-123456789` were redacted while the unsigned `123456789012` and `123456789` were not, so the redaction came from the sign rather than from the digits. All four are now consistent. The engine never detected the unsigned form, so this removes an inconsistency rather than a detection; it is pinned by a regression test so the behaviour cannot drift back unnoticed.

## Known Limitations

Extensionless file names such as `Dockerfile` and `Makefile` are still scored on entropy and may be redacted; they were deliberately left out of the file-name rule in #189 and are unchanged here.

## SDK Changes

`@aragossa/pii-shield-wasi` 2.2.3 (npm) and `pii-shield-wasi` 2.2.3 (PyPI) ship the rebuilt WASM kernel with this fix. SDK APIs are unchanged.
