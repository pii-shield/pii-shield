# PII-Shield v2.2.4 Release Notes

PII-Shield v2.2.4 is a detection release. It ships three detection improvements that were merged after the v2.2.3 tag and three scanner bug fixes found while running the engine over documents rather than logs. One of the fixes closes an under-redaction: a possessive apostrophe (`John's`, `patient's`) silenced the scanner for the rest of the line. There are no breaking changes and no configuration changes; the published WASM kernels for Node and Python are rebuilt with all of it.

## Highlights

- **Built-in secret signatures (#196).** Issuer-prefixed credentials — AWS and Google API keys, GitHub, Slack and Stripe tokens, JWTs, `Bearer` credentials and PEM private-key framing — are now redacted on their format, independent of entropy. A valid-format low-entropy token such as `AKIAAAAAAAAAAAAAAAAA` used to pass; every signature-shaped secret used to pass once an operator raised `PII_ENTROPY_THRESHOLD`. With `PII_ENTITY_TYPE_LABELS=true` the marker names the issuer (`[HIDDEN:aws-key:…]`, `[HIDDEN:stripe-key:…]`); the `piishield_redaction_events_total` metric gains the `type` value `signature`.
- **A possessive apostrophe no longer disables the scanner (#198).** `John's token <secret>` left the secret in place; the same line without the apostrophe redacted it. See Security.
- **Non-Latin text is no longer pushed towards redaction (#195).** Bigrams are scored only on pairs of adjacent ASCII characters, so a Cyrillic, Turkish or CJK word gets no bigram adjustment at all instead of collapsing onto the unknown-bigram default.
- **An `AAAA…` blob is whitelisted only when it is really an SSH key (#197).** The body must decode to a known SSH algorithm; any other base64 blob starting with `AAAA` is scored normally.
- **One invalid regex no longer drops the whole rule list on the SDK path (#199).** See SDK Changes.
- **A short word after a bare sensitive word is no longer redacted (#202).** `pass an extraordinary resolution` keeps `an`; `password hunter2` still redacts `hunter2`.

## Security

Two changes affect false negatives, both in the direction of catching more:

- **Under-redaction fixed (#198).** The quote-aware tokenizer treated a lone `'` as the opening quote of a value. English prose is full of lone apostrophes, so everything after `John's`, `patient's` or `can't` to the end of the line became one unscanned "value". Measured on real text before the fix: 25–28% of lines in two UK court judgments and 20% of clinical queries in a public benchmark carried an unpaired apostrophe. A single quote now opens a value only when a closing one exists later in the same line before a separator, and closes it only when not glued to a letter on its right. Luhn card detection was never affected (it runs on the whole line before tokenisation). No secret rotation is needed: nothing was leaked by the engine itself, lines with this shape were simply not scanned.
- **Signatures (#196)** add deterministic, threshold-independent detection for the issuer formats listed above.

Two changes affect false positives, both reducing them: #195 (non-Latin text) and #202 (short words after a bare key). One narrows a whitelist: #197 — a base64 blob that merely starts with `AAAA` is now redacted unless it decodes to an SSH key; a genuine `ssh-rsa` / `ssh-ed25519` public-key body still passes.

## Bug Fixes

### Possessive apostrophe opened a quoted value (#198)

`scanSegment` opened a quote on any `'`. A possessive apostrophe never gets a partner, so the rest of the line was processed as a single quoted token: anchored custom rules and per-token entropy never ran on it. Regression test `TestPossessiveApostropheDoesNotOpenQuote`; the unbalanced-quote (B3) and quote-preservation (B8) tests are unchanged.

### One invalid rule dropped the whole list on the SDK path (#199)

`ApplyCustomRegexes` and `ApplySafeRegexes` returned on the first pattern that failed to compile, with nothing applied, and the WASM entrypoint discards that error. A single stray bracket in a `custom_regexes` list passed through the Node or Python SDK silently switched off every rule in the list. The CLI environment-variable path already skipped per rule (2.2.0); every path now does: the invalid rule is skipped with a `WARNING` on stderr, the rest are applied, and the Go API returns a `*SkippedRegexRulesError` listing what was dropped. Parity case `invalid_rule_does_not_drop_the_list` runs through Go, Node and Python.

### Short word after a bare sensitive word was force-redacted (#202)

The token after a bare sensitive word is forced, and the forced path skipped `PII_MIN_SECRET_LENGTH`, so `pass an extraordinary resolution` hid `an` and `token to the` hid `to`. The force is now dropped only for a short all-letter word; anything long enough or carrying a digit or symbol (`password: 12345`) stays forced, and `key=value` pairs are untouched.

## Breaking Changes

No breaking changes. No salt, credential, or configuration changes are required.

**Behaviour changes to be aware of:**

- A base64 blob starting with `AAAA` that is not an SSH key is now redacted (#197). If your logs carry such blobs deliberately, add a `PII_SAFE_REGEX_LIST` rule for them.
- Tokens matching a built-in signature are redacted regardless of entropy threshold (#196). Stripe publishable keys (`pk_…`) are deliberately not matched.
- Text in non-Latin scripts is judged on entropy alone (#195); `PII_BIGRAM_DEFAULT_SCORE` no longer influences it.

## Known Limitations

- A multi-word quoted value after `key=` (`note='leak <secret>'`, `msg="user 42 token <secret>"`) is not re-tokenised and is not scanned; a single-word quoted value and a quoted phrase without a key are. Tracked as B15.
- A quoted value under a sensitive key that itself contains `=` (base64 padding) still leaks (B7). Custom regexes still do not run on tokens shorter than 5 characters (B5).

## SDK Changes

`@aragossa/pii-shield-wasi` 2.2.4 (npm) and `pii-shield-wasi` 2.2.4 (PyPI) ship the rebuilt WASM kernel. The 2.2.3 packages did not contain #195, #196 or #197 — those merged after the 2.2.3 tag — so this is the first SDK release with the signature detectors. SDK APIs are unchanged. Invalid `custom_regexes` / `safe_regexes` entries are now skipped individually with a stderr `WARNING` instead of dropping the whole list; the SDK READMEs describe the new behaviour.

## Upgrade Notes

```bash
helm repo update
helm upgrade pii-shield pii-shield/pii-shield --version 2.2.4
helm upgrade pii-shield-operator pii-shield/pii-shield-operator --version 2.2.4
```

```bash
npm install @aragossa/pii-shield-wasi@2.2.4   # Node
pip install --upgrade pii-shield-wasi==2.2.4  # Python
```

Builder images moved to `golang:1.27.1` and the operator to `controller-runtime` v0.25.0 (dependabot); the Go toolchain directive stays at 1.26.5.
