# PII-Shield v2.2.8 Release Notes

PII-Shield v2.2.8 is a detection release. It collects ten scanner fixes merged since v2.2.7: eight close under-redactions, one removes over-redaction, and one stops adding quotes the input did not have. It also makes the scanner usable as a Go library (`go get github.com/pii-shield/pii-shield/v2/pkg/scanner`), builds every artifact with Go 1.27.2, and adds the Chinese and Japanese words for password and token to the default sensitive keys. There are no breaking changes for CLI, container, Helm or SDK users. The published WASM kernels for Node and Python are rebuilt with all of it.

## Highlights

- **The scanner is a Go library (#276).** The module path is now `github.com/pii-shield/pii-shield/v2`, so `go get` accepts the v2 tags. Before, `go get …@v2.2.7` failed and `@latest` resolved to v1.4.2.
- **A secret in a quoted phrase next to a URL is hidden (#278).** `curl -H 'Authorization: Bearer <key>' https://…` logged as one JSON string, and `msg="fetched https://… with Bearer <key>"`, passed whole.
- **A sensitive key keeps its force across a spaced separator (#281, #286).** `api_key = <value>`, `key = <base64>` and `Authorization = Basic <base64>` were judged by score alone, while `api_key=<value>` was hidden.
- **Numeric session ids under a cookie or session key are hidden (#280).** `Cookie: 8092026976377529079` passed in 59 of 60 runs.
- **Chinese and Japanese password keys (#287).** `密码：hunter2x` passed; the full-width colon now splits key and value, and `密码`, `口令`, `密钥`, `令牌`, `パスワード` are default sensitive keys.

## Features

### Go library (#276)

```bash
go get github.com/pii-shield/pii-shield/v2/pkg/scanner
```

```go
import "github.com/pii-shield/pii-shield/v2/pkg/scanner"

clean := scanner.ScanAndRedact(line)         // one line
cleanText := scanner.ScanAndRedactText(text) // several lines, line endings kept
```

The package needs only the standard library and reads the same `PII_*` environment variables as the CLI. v2.2.8 is the first tag `go get` accepts. The operator module is separate and unchanged.

### Full-width colon and CJK sensitive keys (#287)

A token with no ASCII `:`, `=` or quote of its own is split on the full-width colon `：` (U+FF1A), and the value is processed under the key's sensitivity, as after an ASCII colon. The default `PII_SENSITIVE_KEYS` gain `密码`, `口令`, `密钥`, `令牌` and `パスワード`. They are substring entries like the rest. An ASCII key is matched against the ASCII entries only, so the new entries cost the English path nothing.

120 weak passwords after `密码：` and `パスワード：`: 47 leaked on 2.2.7, 0 now; the key was swallowed into the marker in 73, 0 now. 60 benign lines such as `用户：张三 状态：成功` are unchanged.

## Security

### Under-redaction fixed

Each of these shapes passed in the clear on 2.2.7:

- **A secret in a quoted phrase that holds a URL (#278).** The URL check ran before the quoted phrase was split, so only the query and the URL password were looked at. `{"command": "curl -H 'Authorization: Bearer <key>' https://api.example.com/v1/me"}`, `{"command":"token=<key> https://api.example.com/"}` and `level=info msg="fetched https://api.example.com/x with Bearer <key>"` came back unchanged in 20 of 20 runs. Such a phrase is now scanned word by word; the URL inside still gets the URL handling. A phrase that opens with a product/version token (a User-Agent) stays on the old path.
- **A Gigya login token ending in `.sc3` (#279).** `Cookie: st2.s.<34>.<80>.<50>.sc3` was taken for a file name because of its short last part, 60 of 60 runs. A token with a part of 32 or more characters that mixes capitals, small letters and digits is no longer a file name. Built file names with a hex hash, UUID file names and long camelCase names are still file names.
- **A numeric session id under a cookie or session key (#280).** 10 or more digits as the value of a key whose last word is `cookie`, `session`, `sid`, `sessionid`, `jsessionid`, `phpsessid`, `sessid` or `session id` are now hidden, also in a URL query (`?JSESSIONID=…`). Marker label `key`. `cookie_consent=true`, `session: 3` and digits under `user_id` or `order_id` are unchanged.
- **`Authorization = Basic <base64>` and `Authorization=Basic <base64>` (#281).** A header logger that writes `name = value` let the credential through in 8 of 150 runs and left the `==` padding outside the marker in 102; a Java `Map` printed with `toString()` (`headers={Authorization=Basic …}`) leaked it in 12 of 150. Both are 0 now. A word that reads as English after `Basic` (`Authorization: Basic support`) is no longer taken for a credential.
- **A base64 value shortened with three dots (#282).** Code that prints `value[:30] + "..." + value[-20:]` leaves 30 characters readable, and `sgcookie: E100B3V0nvPq…dLGyGWH3aqQD/akk47==` came back unchanged: the `==` padding was taken for a key/value separator. In 160 random values the head stayed readable in 120 on 2.2.7, in 1 now.
- **A base64 value that starts with `/` (#285).** About one base64 value in 64 starts with a slash and was taken for a Unix path. A token with a leading `/` and no other `/` is now a path only when the segment reads as a name (`/tmp`, `/app.log`, `/wp-login.php`). 160 random values: 160 leaked on 2.2.7, 92 now; every one left has a second `/` inside.
- **A sensitive key followed by a lone `=` or `:` (#286).** `api_key = <value>`, `client_secret = <value>` and `key = <base64>` went by score, because the lone separator spent the key's forced slot. The force now carries across it onto a value of at least `MinSecretLength` with a digit or a symbol, so `key = value`, `secret = None` and `api_key = api_key if …` keep their words. 40 random values per shape: `api_key = <human-style password>` 20 leaked, 0 now; `Header: api_key = <value>` 22, 0 now.
- **A Chinese or Japanese password key with a full-width colon (#287).** See Features.

### Over-redaction fixed

- **An account label in CJK brackets (#283).** `【acct_1】  1. cookie2: <hex>` lost the label at the start of every line, while `[acct_1]` was kept. CJK and full-width brackets (`【】「」『』〔〕〈〉《》〖〗（）［］｛｝`) are now token separators; a secret inside them is still hidden, scored on its own.
- **A word after `Basic` (#281).** `auth = basic support` and `Authorization: Basic support` no longer hide the word.

## Bug Fixes

- **No quotes around the marker of a bare number after an unquoted key (#284).** `token: 8092026976377529079` came back as `token: "[HIDDEN:…]"`. The marker is quoted only when the key before it was quoted, so `{"token": 8092026976377529079}` still becomes valid JSON `{"token": "[HIDDEN:…]"}`, also with spaces around the colon.

## Breaking Changes

None for the CLI, the container images, the Helm charts and the SDKs.

**Behaviour changes to be aware of:**

- **Go import path.** Code that imported `github.com/pii-shield/pii-shield/pkg/scanner` by a commit pseudo-version must switch to `github.com/pii-shield/pii-shield/v2/pkg/scanner` (#276).
- **More values are hidden.** Numeric session ids under cookie and session keys; values after a sensitive key and a spaced `=` or `:`; values after the five CJK keys, including a short all-letter value glued to the key by `：` (`密码强度：弱`), the same as `password_strength:weak`.
- **Marker quoting (#284).** A hidden bare number after an unquoted key is no longer quoted. A rule that matched `Code: "[HIDDEN:…]"` downstream must match `Code: [HIDDEN:…]`.
- **Measured on real logs.** Every scanner PR was checked against 300 000 access-log lines and 16 143 application-log lines: 0 lines changed. Smoke stayed at 431 TP / 569 TN / 0 FP / 0 FN, and benchstat showed no throughput change beyond noise.

## Known Limitations

Still open from the fixes above:

- A base64 value with a `/` inside (`/Ny/ilcc4ho…`) still reads as a path of several segments. Treating every segment as a value hid it, but changed 112 644 of 300 000 access-log lines, so it was rejected (#285).
- A letters-only value after a spaced separator (`client_secret = QqQRNISrKSk`) is judged by score, the same limit as `password is swordfish` (#286).
- A User-Agent with no URL can lose its bot name and contact address (`(compatible; AhrefsBot/6.1)`), as on 2.2.7 (#278).

- Dependency updates: `github.com/prometheus/client_golang` 1.24.1 -> 1.25.0 (#289); operator `github.com/onsi/ginkgo/v2` 2.33.0 -> 2.33.1 (#291); GitHub Actions `reviewdog/action-actionlint` 1.78.1 -> 1.80.2, `github/codeql-action` 4.38.2 -> 4.39.0, `actions/setup-node` 7.0.0 -> 7.1.0, `actions/upload-artifact` 7.0.1 -> 7.0.2, `actions/download-artifact` 8.0.1 -> 8.0.2, `goreleaser/goreleaser-action` 7.2.3 -> 7.3.0, `ossf/scorecard-action` 2.4.4 -> 2.5.0 (#290, #292).
